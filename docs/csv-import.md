# CSV 가져오기·내보내기

가져오기 단위는 **라이선스 기록 한 줄**입니다. 순서: 파일 선택 → 컬럼 연결 → 검증 미리보기 → 최종 저장.
오류가 한 줄이라도 있으면 아무것도 저장하지 않습니다(전체 성공 또는 전체 취소).

- 파일 형식: UTF-8 CSV(BOM 있어도 됨), 첫 줄 머리글, RFC 4180 따옴표 규칙.
- 예제: [`examples/import-example.csv`](../examples/import-example.csv) (개인정보 없음). 앱의 '양식 저장'도 같은 파일을 만듭니다.

## 열 설명(기본 양식)

| 열 | 필수 | 설명 |
|---|---|---|
| `management_ref` | | 외부 관리 번호(주문 번호 등). 라이선스의 '외부 관리 번호'로 보관 |
| `customer_id` | △ | 이 프로그램의 기존 고객 내부 ID. 있으면 그 고객에 연결 |
| `customer_name` | △ | 고객명/업체명. `customer_id`가 없으면 **새 고객**을 만든다(이름만으로 기존 고객과 병합하지 않음) |
| `customer_contact` | | 새 고객의 담당자 |
| `product_code` | ○ | 사전 등록된 제품 코드(관리용 코드 또는 공통 형식 코드). 모르는 코드는 오류. 화면에서 '모든 행의 제품'을 고르면 생략 가능 |
| `pc_scheme` | | `lms-pc-v1` / `rentaldesk-machine-v0` / `reviewcut-install-id` / `manual`. 비우면 번호 모양으로 정하고 미리보기에 안내 |
| `pc_number` | ○ | PC 번호. 체계별 정규화(공통·RentalDesk: 공백·하이픈 제거, 대문자). `manual`·`reviewcut-install-id`는 앞뒤 공백만 제거(앞자리 0, 대소문자 보존) |
| `pc_alias` | | PC 별칭 |
| `starts_at` | △ | 시작 시각. 아래 '시각 형식'. 비우면 `issued_at` |
| `expires_at` | | 만료 시각(**미포함**, 이 시각부터 만료). 날짜만 쓰면 오류 — 날짜는 `last_use_day` 사용 |
| `last_use_day` | | 마지막 사용일(서울, `YYYY-MM-DD`). 다음 날 서울 00:00이 만료 시각. `expires_at`과 함께 쓰면 값이 같아야 함 |
| `issued_at` | △ | 발급 시각. 비우면 `starts_at` (`starts_at`·`issued_at` 중 하나는 필수) |
| `status` | | `issued`(기본) / `cancelled` / `superseded` 또는 `발급됨` / `취소됨` / `대체됨` |
| `file_license_id` | | 라이선스 파일 안의 라이선스 ID. 중복 판정에 최우선으로 쓴다 |
| `generator` | | `lms-license-v1` 등. 비우면 PC 번호 체계로 정함 |
| `edition`, `max_version` | | 발급 당시 조건(참고용으로 보관) |
| `memo` | | 메모 |
| `source_id` | | 원본 식별자. 같은 파일을 다시 가져올 때 중복 판정에 쓴다 |

만료 시각과 마지막 사용일을 모두 비우면 **영구**(만료 없음, DB에 NULL)입니다.

### 시각 형식

- `2026-10-23T05:00:00Z` — UTC
- `2026-10-23` — 서울 날짜 00:00
- `2026-10-23 14:30` 또는 `2026-10-23 14:30:00` — 서울 시각

DB에는 UTC로 저장하고 기간은 `[시작, 만료)`로 판정합니다.

## 검증과 중복

- 행 번호(머리글 = 1번째 줄)와 함께 표시: 필수값 누락, 알 수 없는 제품, 날짜 오류, PC 번호 형식 오류, 다른 고객 소유 PC, 파일 안 중복, 기간 중복.
- **중복 판정 키**: `file_license_id` > `source_id` > (제품 + `management_ref`) > 행 내용 해시. 이미 가져온 키는 **건너뜀**으로 표시하고 다시 저장하지 않습니다. 같은 파일을 다시 가져와도 중복이 생기지 않습니다.
- 이 프로그램에서 내보낸 CSV(`source_id = lms:<관리 번호>`)를 같은 DB로 다시 가져오면 이미 있는 기록은 건너뜁니다.
- 기간 중복: 같은 제품·PC에 '발급됨' 기록끼리 기간이 겹치면 오류. '파일 안에서 겹치면 앞 기록을 대체됨으로 가져오기'를 켜면 파일 안의 앞 기록을 '대체됨'으로 하고 갱신 관계로 연결합니다(재발급 이력). 이미 DB에 있는 기록과 겹치면 항상 오류입니다.
- 가져온 기록은 라이선스 파일이 없으므로 `호환성 미검증`으로 표시합니다.

## RentalDesk 발급 내역(`issued_licenses.csv`)

RentalDesk 발급 도구(`scripts/generate_license.py`)의 키 폴더(`~/RentDeskSellerKeys/`)에 있는 발급 내역을 바로 가져올 수 있습니다. 머리글에 `machine_code`, `customer_label`이 있으면 자동으로 이 양식을 고릅니다.

| 발급 내역 열 | 연결 |
|---|---|
| `license_id` | 파일 안 라이선스 ID |
| `issued_at_utc` | 발급 시각 |
| `customer_label` | 고객명 **후보**(기존 고객과 자동 병합하지 않음. 파일 안 같은 이름은 한 고객으로 묶는 옵션 있음) |
| `machine_code` | PC 번호 |
| `edition`, `updates_through`, `package`, `app_version` | 발급 당시 조건으로 보관 |
| `expires_at_utc` | 만료. 이전 형식(23:59:59 서울)은 관리 기준 다음 날 00:00으로 바꿔 저장하고 원래 값도 남김 |
| `note` | 메모 |
| `kmong_order` | 외부 관리 번호 |
| `format` | `v1`이면 `lms-pc-v1` + 공통 형식, 아니면 `rentaldesk-machine-v0` + 이전 형식 |
| `starts_at_utc` | 시작(비면 발급 시각) |

예전 파일(앞쪽 7열 또는 11열만)도 그대로 읽습니다. 발급 내역에는 제품 열이 없으므로 '모든 행의 제품'에서 RentalDesk를 고르세요.

## 내보내기

- 라이선스 화면의 **현재 검색어·필터 결과**를 내보냅니다. 열은 위 양식과 같고 `management_no`, `pc_display`, `effective_status`, `verification`, `issue_method`가 더 붙습니다.
- UTF-8(BOM 포함), 줄바꿈 CRLF. PC 번호의 앞자리 0과 한글을 그대로 씁니다.
- `customer_id`는 이 DB의 내부 ID입니다. 다른 DB로 옮길 때는 컬럼 연결에서 '연결 안 함'으로 두세요.

### 수식 실행 위험 처리 정책

- `=`, `+`, `-`, `@`, 탭, CR로 시작하는 셀은 표 계산 프로그램에서 수식으로 실행되지 않도록 **앞에 작은따옴표(`'`)를 붙여** 저장합니다.
- 이 프로그램으로 다시 가져올 때는 `'` 다음 글자가 위 문자이면 작은따옴표를 떼어 원래 값으로 되돌립니다.
- 엑셀에서 열 때 앞자리 0이 사라지는 것은 엑셀의 표시 문제입니다(파일 값은 보존). '데이터 가져오기'에서 해당 열을 텍스트로 지정하세요.
- 라이선스 원문은 CSV에 넣지 않습니다. 고객에게 보낼 파일은 라이선스 상세의 '라이선스 파일 저장'을 쓰세요.
