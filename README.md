# 라이선스 관리 (판매자용 macOS 앱)

여러 판매 프로그램의 고객·제품·PC 번호·라이선스·발급 이력을 한곳에서 관리하고, **이 앱에서 라이선스를 직접 발급**합니다.
인터넷·서버 없이 판매자의 Mac에서만 동작합니다. 고객에게 배포하는 프로그램이 아닙니다.

- 공통 형식 v1(`lms-license` v1) 자동 발급 — 새 제품도 코드 수정 없이 제품 등록 + 서명 키만으로 발급
- 이미 판매한 앱의 이전 형식: ReviewCut 0.1(설치 ID), RentalDesk 1.0(20자 기기 코드)
- 기존 라이선스 파일 수동 등록(서명 검증 후 내용 자동 채움), 외부 라이선스 기록
- 갱신·PC 교체·취소 이력, 기간 중복 차단, 통합 검색, 대시보드, CSV 가져오기·내보내기, 백업·복원

> 현재 상태: 소스와 테스트 작성 완료, **macOS에서 빌드·테스트 실행 전**입니다. 자세한 범위와 남은 확인 항목은 [docs/implementation-status.md](docs/implementation-status.md)를 보세요.

## 1. 요구 환경과 버전

| 항목 | 버전 |
|---|---|
| macOS | 14(Sonoma) 이상 |
| Xcode | 16 이상(Swift 6 도구, 언어 모드는 Swift 5) |
| GRDB.swift | 7.x(7.10.0 이상, 8.0 미만) — SQLite 접근 |
| 서명 | Apple CryptoKit `Curve25519.Signing`(Ed25519) |

처음 `swift build`를 하면 `Package.resolved`가 생깁니다. 버전 고정을 위해 이 파일을 커밋하세요.

## 2. 빌드·실행·테스트

```bash
swift build                 # 빌드
swift test                  # 단위 테스트(테스트 벡터, 이전 형식 호환, 업무 규칙, CSV, 백업)
swift run LicenseManager    # 개발 중 바로 실행
tools/verify_generated_with_apps.sh   # 이 앱이 만든 이전 형식 파일을 두 고객 앱의 실제 검증 코드로 확인
```

`tools/verify_generated_with_apps.sh`는 옆 폴더의 `../cut_review`(Node 22.6 이상)와 `../rental_management_system`(가상환경 `.venv`에 PyNaCl)이 필요합니다.

Xcode에서 열려면 `Package.swift`를 열고 `LicenseManager` 스킴을 실행합니다.

### 배포 파일(.app, .dmg)

```bash
scripts/build_app.sh                                   # 임시(ad-hoc) 서명
scripts/build_app.sh --sign "Developer ID Application: 이름 (TEAMID)" --notarize 프로필이름   # 정식 서명·공증
```

결과는 `dist/라이선스 관리.app`, `dist/LicenseManager-1.0.0.dmg`입니다.

- **서명·공증 여부**: 기본 스크립트는 공증하지 않습니다(임시 서명). 판매자 본인만 쓰는 도구라 공증 없이도 됩니다.
- **미서명(임시 서명) 앱 처음 실행**: Finder에서 앱을 Control-클릭 → '열기' → '열기'. 또는 시스템 설정 → 개인정보 보호 및 보안 → '그래도 열기'.
- 임시 서명 앱을 다시 빌드하면 서명이 바뀌어, 키체인 접근 시 macOS가 "허용"을 물을 수 있습니다. '항상 허용'을 누르세요.

| 내용 | 위치 |

- DB와 백업에는 **고객 정보와 라이선스가 들어 있고, 암호화되어 있지 않습니다.** FileVault를 켜고 백업 파일 보관에 주의하세요.
- 관리자 권한이 필요 없습니다. 같은 DB를 쓰는 앱은 한 번에 하나만 실행됩니다. 네트워크 공유 폴더의 DB를 여러 PC에서 함께 쓰는 방식은 지원하지 않습니다.

## 4. 처음 설정

1. **제품 → '기존 제품(ReviewCut·RentalDesk) 설정 추가'**: 두 제품을 생성 방식(공통 형식 + 이전 형식)과 고객 앱 공개키와 함께 등록합니다.
2. **서명 키 가져오기**(제품 상세 → 키 추가 → 기존 비밀키 가져오기). 새로 만들지 마세요 — 이미 배포한 앱이 새 키를 인정하지 않습니다.
   - ReviewCut: Windows PC의 `%USERPROFILE%\ReviewCut-license-keys\prod-2026.private.pem`(PKCS#8 PEM)을 Mac으로 안전하게 옮긴 뒤 선택. `key_id = prod-2026`.
   - RentalDesk: `~/RentDeskSellerKeys/signing_key.json`(파일의 `private_key_hex` 사용). `key_id = rentaldesk-2026`.
   - 가져온 비밀키의 공개키가 고객 앱에 들어 있는 공개키와 다르면 **거부**합니다. 같은 키를 공통 형식과 이전 형식이 함께 씁니다(공통 형식은 서명 대상 앞에 `lms-license-v1:`을 붙여 섞이지 않음).
   - 가져온 뒤 원본 비밀키 파일은 안전한 오프라인 위치에 보관하세요.
3. 고객 등록 → 고객이 보낸 PC 번호 등록 → 라이선스 발급.

## 5. 자동 발급

상단 **'라이선스 발급'**(⌘N) 또는 고객 상세의 버튼. 순서: 고객 → 제품 → PC → 영구/기간제 → 시작·만료 → 메모.

- 생성 방식은 PC 번호 체계로 자동 선택합니다: 25자 → 공통 형식 v1, 20자 → RentalDesk 이전 형식, `VRN-` → ReviewCut 이전 형식.
- 시각은 서울 기준으로 입력·표시하고 DB에는 UTC로 저장합니다. 기간은 `[시작, 만료)`이며, 화면에 '포함되는 마지막 날짜'와 '실제 만료 시각'을 함께 보여줍니다. 예) 2026-11-24까지 사용 → 만료 시각 2026-11-25 00:00(서울).
- 기간을 개월 수로 정하면 기존 발급 도구와 같은 규칙(시작일 + N개월 같은 날짜까지, 없으면 말일)입니다.
- 지원하지 않는 조건은 입력 단계에서 막습니다: ReviewCut 이전 형식은 영구만, RentalDesk 이전 형식은 미래 시작 불가.
- 발급 직후 만든 파일을 등록된 공개키로 다시 검증하고, 통과했을 때만 저장합니다(대체 처리·저장·감사 기록이 한 트랜잭션).
- 발급 후 **라이선스 문자열 복사 / 라이선스 파일 저장(UTF-8 원본) / 텍스트(.txt) 저장**. 저장에 실패해도 다시 발급하지 않고 상세 화면에서 다시 저장할 수 있습니다.
- RentalDesk 이전 형식 파일에는 마지막 사용일 23:59:59(서울)가 기록되고, 관리 DB에는 다음 날 00:00으로 저장합니다. 발급 조건 스냅샷에 파일 값이 그대로 남습니다.

## 6. 수동 등록

- 발급 창에서 **'기존 파일 수동 등록'**: 파일을 고르거나 문자열을 붙여 넣습니다. 공통·이전 형식이면 제품에 등록된 공개키로 서명을 검증하고 PC 번호·기간·라이선스 ID를 파일에서 채웁니다.
- 검증에 실패하거나 형식을 모르면 **`호환성 미검증`**으로 등록합니다. 이때 입력한 기간은 '관리상 기간'일 뿐 고객 프로그램이 강제한다는 뜻이 아닙니다.
- 비밀키가 없어도 **'고객 앱 공개키만 등록'**을 하면 수동 등록 파일의 서명을 확인할 수 있습니다.
- **여러 파일 일괄 등록**(가져오기·내보내기 → 라이선스 파일 일괄 등록): ReviewCut처럼 발급 내역 파일이 없는 제품용. 서명이 확인된 파일만 받으며, 하나라도 문제가 있으면 전체를 저장하지 않습니다. 고객은 파일의 PC가 이미 등록되어 있으면 그 고객, 아니면 표시명으로 새 고객(기존 고객과 이름으로 자동 병합하지 않음)입니다.

## 7. 갱신·PC 교체·취소

- **갱신**: 새 라이선스를 발급하고 이전 라이선스와 연결합니다. 기본 시작은 '현재'와 '기존 만료' 중 늦은 시각. 이전 형식처럼 미래 시작을 못 하거나 기존이 영구면 시작을 현재로 하고 기존을 같은 트랜잭션에서 '대체됨' 처리합니다(확인 후 진행).
- **PC 교체**: 새 PC에 새 라이선스를 발급하고 기존을 '대체됨' 처리합니다. 사유 필수.
- **취소**: 사유 필수, 기록은 삭제하지 않고 '취소됨'으로 남습니다.
- 처리 상태(발급됨·취소됨·대체됨)와 시간으로 계산하는 유효 상태(사용 전·유효·만료)를 구분하고, 취소·대체가 우선합니다.
- 같은 제품·PC에 '발급됨' 라이선스의 기간이 겹치면 막습니다(만료 없음 = 무한대, 미래 시작 포함).

> **오프라인 취소의 한계**: 오프라인 라이선스는 이 앱에서 취소·대체해도 **고객 PC에 이미 전달된 라이선스가 원격으로 중지되지 않습니다.** 앱의 기록은 관리용입니다.

## 8. 새 제품 추가(공개키를 고객 앱에 넣는 방법)

1. 제품 → 제품 등록: 제품명, 제품 코드, 생성 방식 '공통 형식 v1', **공통 형식 제품 코드**(`^[A-Z][A-Z0-9_]{1,31}$`, 예 `MYAPP`), 기본 에디션, 기본 사용 가능 최고 버전(`주.부`, 비우면 제한 없음), 기본 기간.
2. 제품 상세 → 키 추가 → **새 키 쌍 만들기**: `key_id`(예 `myapp-2026`)를 정합니다. 비밀키는 키체인에만 저장됩니다.
3. **'key_id 복사', '공개키(hex) 복사' 또는 '공개키(PEM) 복사'**로 값을 가져와 고객 앱의 `(key_id, 공개키)` 목록에 넣습니다. 고객 앱은 [`docs/license-format-v1.md`](docs/license-format-v1.md) 규격대로 검증하고, 앱의 제품 코드는 공통 형식 제품 코드와 같아야 합니다.
   - TypeScript 예: `createPublicKey(PEM)` / Python 예: `VerifyKey(bytes.fromhex(hex))`
   - 고객 앱 구현은 [`docs/license-v1-test-vectors.json`](docs/license-v1-test-vectors.json)을 통과해야 합니다.
4. 키를 교체할 때는 이전 공개키를 앱에 남겨 두어야 기존 라이선스가 계속 인정됩니다.

### 비밀키 백업

제품 상세 → 서명 키 → '…' → **비밀키 내보내기**. 경고를 확인하면 사용자가 고른 위치에 권한 600 PKCS#8 PEM으로 저장합니다. 저장소·클라우드 동기화 폴더가 아닌 오프라인 매체에 보관하세요. 비밀키는 DB·일반 백업·로그·CSV에 들어가지 않습니다.

## 9. 백업·복원

- **수동 백업**(백업·설정 → 지금 백업): 원하는 위치에 저장, 자동 삭제하지 않습니다.
- **자동 백업**: 앱 종료 시 `Backups/auto-*.sqlite`, 기본 최근 30개 유지(설정에서 변경). 실패하면 조용히 넘어가지 않고 '다시 시도 / 백업 없이 종료 / 종료 취소'를 묻습니다.
- SQLite 온라인 백업 API를 씁니다(실행 중인 DB 파일을 단순 복사하지 않음). 라이선스 파일은 DB에 BLOB으로 있어 백업과 어긋나지 않습니다.
- **복원**: 임시 복사본으로 무결성 검사·스키마 버전·프로그램 호환성을 확인 → 현재 데이터를 `Backups/pre-restore-*.sqlite`로 따로 백업 → 연결을 닫고 교체 → 다시 열기. 실패하면 기존 데이터로 되돌립니다. 손상되었거나 더 새로운 버전의 백업은 현재 DB를 건드리지 않고 거부합니다.
- 스키마 업그레이드 전에는 `Backups/pre-migration-*.sqlite`를 자동으로 만듭니다.
- 서명 비밀키는 백업에 없습니다. **다른 Mac에서 복원하면 제품별 서명 키를 다시 가져와야** 자동 발급할 수 있습니다(DB에 있는 공개키·`key_id`로 맞는 키인지 확인).

## 12. 소스 구성

```
Sources/LicenseCore     라이선스 형식·생성기(LicenseGenerator 프로토콜, 내장 3종)·정규화 JSON·Ed25519 키·시각 규칙
Sources/LicenseStore    GRDB 스키마/마이그레이션, 업무 규칙 서비스, CSV, 백업, 키체인, 경로·단일 실행 잠금·로그
Sources/LicenseManager  SwiftUI 화면(MVVM: AppModel + 뷰)
Tests/                  테스트 벡터·이전 형식 호환·업무 규칙·CSV·백업 테스트
docs/                   규격, 테스트 벡터, 이전 형식 고정 예제, CSV 설명, 구현 상태
```
